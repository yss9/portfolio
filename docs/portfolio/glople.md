# Glople · 팀 추천 서비스에서 개인 모델 학습까지

## 기여의 시점

2024년 3월부터 11월까지, 7인 팀에서 키워드 여행지 추천과 유사 여행자 루트 추천, 추천 화면 일부를 담당했다. 당시 팀 챗봇은 STOMP 메시지를 Spring에서 받아 OpenAI GPT-3.5 Turbo에 전달했다. 2026년 10월부터는 개인 개편으로 여행지 데이터를 수집하고, 태깅·검색·도구 호출을 각각 학습해 화면에 연결했다. 기존 챗봇과 새 여행 도우미는 사용자 진입점과 구현이 다르다. 개편 코드는 [Glople main에 병합된 PR #106](https://github.com/yss9/Glople/pull/106)에서 확인할 수 있다.

## 기존 소개에서 이어갈 부분

기존 포트폴리오의 핵심은 추천 요청에서 읽고 정렬하는 데이터의 양을 줄인 일이다. 94개 키워드를 두 개의 63비트 마스크에 담아 DB에서 겹치는 수를 세고 상위 21곳을 반환한다. 유사 사용자 추천은 후보를 좁힌 뒤 코사인 유사도와 크기 12의 우선순위 큐로 루트를 고른다. 동일 데이터·시나리오의 로컬 JMeter 측정에서 키워드 추천 p95는 20→10ms, 유사 사용자 추천 p95는 33→9ms였다. 아래의 품질 평가는 별도 실험이다. [기존 소개](../../src/content/projects/glople.ts)

## 여행 도우미가 도구를 고르고 결과를 읽는 과정

1. Apple Silicon에서 MLX로 4비트 Qwen3-4B-Instruct-2507의 기본 가중치를 고정하고 LoRA를 학습했다. 추천·상세·후기·일정 저장 등 도구 8개의 이름과 인자, 되묻기·직답을 학습 데이터에 담았다.
2. `/assistant`에서 요청을 받으면 LangGraph가 로컬 모델 서버의 호출 제안을 받아 인자와 사용자 발화의 근거를 확인한다. 조회 결과 카드를 먼저 보내고 답변을 SSE로 이어 보낸다. 일정은 초안에서 수정·승인한 뒤 저장하며 `/my/plans`에서 확인한다.
3. 같은 첫 판단 시험 300문제에서 기본 모델 정답률은 58.7%, v3는 91.0%, v4는 87.0%였다. 반면 정답 호출을 미리 주고 결과를 읽게 한 별도 161문제에서는 일반 루프의 근거 있는 답변이 v3 128건에서 v4 159건으로 늘었다. 첫 판단에 v3, 도구 결과를 받은 다음 턴에 v4를 쓰는 구성을 비교한 이유다.
4. Git에는 학습 스크립트·설정·평가표·서빙 클라이언트가 있다. 실제 모델을 실행할 때는 가중치와 LoRA 어댑터를 별도로 준비한다. 합성 시험 점수와 실제 여행자 대화 성공률은 각각 따로 측정해야 한다.

## 포트폴리오에 쓸 문장

> 팀 프로젝트에서 개발한 여행 추천 서비스를 개인적으로 확장했습니다. 여행 질문에 맞는 도구와 인자를 고르도록 Qwen3-4B를 QLoRA로 학습해 동일한 첫 판단 평가 300문제에서 정답률을 58.7%에서 91.0%로 높였습니다. LangGraph에서 모델이 고른 인자를 검증하고, 일정 초안은 사용자가 확인한 뒤 저장하도록 연결했습니다.
