# MOFY · 패션 마켓에서 사용자 간 쪽지를 연결한 경험

## 서비스와 개인 기여

7인 팀의 패션 커뮤니티에서 사용자는 데일리룩을 공유하고, 사진 속 의상 색을 팔레트로 확인하거나 중고 거래글을 탐색한다. 이 중 팀원과 공동 구현한 부분은 판매글에서 진입하는 사용자 메시지 기능이다. 기존 포트폴리오는 색상 추출 과정을 상세히 보여준다. 개인 기여를 소개하는 첫 화면에는 구매자가 판매자에게 문의를 보내고 양쪽 보관함에서 확인하는 과정을 배치할 수 있다. [기존 소개](../../src/content/projects/mofy.ts)

## 발신자와 수신자가 다른 목록을 보는 과정

| 화면 | 요청 | 서버에서 결정하는 값 |
| --- | --- | --- |
| 메시지 작성 | `POST /chat/` | 요청의 수신 아이디에 해당하는 사용자를 찾고 인증된 요청자를 발신자로 저장 |
| 보낸 메시지함 | `GET /message_box/1/` | 로그인 사용자가 발신자인 메시지를 조회 |
| 받은 메시지함 | `GET /message_box/2/` | 로그인 사용자가 수신자인 메시지를 조회 |
| 상세 화면 | `GET /message_detail/<id>/` | 선택된 메시지 한 건의 데이터를 직렬화해 표시 |

프론트에서는 작성 요청에 Bearer 토큰을 넣고, 보낸 메시지함의 임시 주소와 받은 메시지함의 더미 목록을 실제 API 응답에 연결했다. 작성 화면에서 수신자와 내용을 입력해 저장하고, 두 계정의 서로 다른 목록에서 같은 쪽지의 방향을 확인하는 흐름이다. 화면 버튼의 이름이 ‘1:1 채팅하기’여도 확인한 구현은 HTTP 요청 기반 메시지함이다. ## 함께 설명할 팀 기능과 사후 작업

팀의 팔레트 기능은 업로드한 사진에서 배경을 제거한 뒤 주요 색을 추출해 팔레트 이미지를 만든다. 공통 게시글 모델은 타입으로 커뮤니티·의상·거래글을 구분한다. 이 내용은 메시지를 보내게 되는 서비스 맥락으로 쓴다. 2025년 3월의 후속 작업에서는 팀 백엔드를 현재 저장소로 통합하고 마이그레이션과 설치 의존성을 정리했다. 메시지 API 공동 구현과 저장소 정리는 서로 다른 시점의 기여다. [도메인 모델](https://github.com/yss9/Mofy/blob/master/backend/community/models.py) · [담당 범위와 후속 작업](https://github.com/yss9/Mofy/blob/master/README.md)

> 중고 거래글에서 판매자에게 문의를 보낼 수 있도록 Django REST Framework API와 React 메시지함을 팀원과 함께 연결했습니다. 발신자는 인증된 사용자로 결정하고 받은 쪽지와 보낸 쪽지를 각자의 보관함에서 확인하도록 했습니다.
