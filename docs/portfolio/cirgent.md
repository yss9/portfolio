# CIRGENT · 검토 결과를 보존하며 회로도 렌더링 줄이기

## 담당과 자료 범위

6인 팀에서 결과 검토·작업 이력·인증·랜딩 화면과 프론트엔드 성능 개선을 맡았다. 사용자는 데이터시트에서 도출된 규칙을 BOM·넷리스트와 대조한 뒤, CHECK 판정의 기준값·설계값·관련 핀을 확인하고 수동 판정을 남긴다. 규칙 추출 모델의 학습·정확도는 담당 프론트엔드 성과와 별도 항목이다. 원본 소스는 비공개다. 이 문서는 공개 가능한 프로젝트 설명과 기존 측정 기록에 근거한다. [기존 소개와 측정 조건](../../src/content/projects/cirgent.ts)

## 클릭 하나에 어떤 계산이 다시 실행됐는가

넷 하나를 선택해도 선택 상태 객체가 바뀌면서 관련 없는 SVG 요소까지 변경을 전달받았다. 개별 요소가 실제로 강조되는지만 전달해도 부모가 약 2,600개를 다시 순회했다. 함께 선택 상태가 바뀌는 핀 행을 그리기 순서대로 묶어 비교 단위를 약 330개로 줄였다. 이 순서를 보존해야 같은 SVG를 사용하는 화면과 PDF·이미지 내보내기에서도 선·강조의 겹침이 유지된다. 개선 뒤 블록·강조·팔레트·표시 모드를 조합한 SVG 252종의 해시가 전후 일치했다.

부품 목록은 별도 병목이었다. 핀을 선택할 때마다 210개 블록의 판정 집계를 되풀이해, 핀 선택과 판정 변경을 분리하고 목록 행을 재사용했다. 작업 이력에서는 원본 리포트와 변환 조건을 기준으로 보드 변환 결과를 캐시하고, 사용자가 바꾼 판정은 최신 상태로 적용했다. 검토 직후 다른 화면으로 이동할 때도 저장 대기 중인 변경값을 공유해 이전 판정으로 돌아가는 현상을 다뤘다.

| 사용자가 한 일 | 측정한 대상 | 결과와 해석 |
| --- | --- | --- |
| 대형 IC에서 넷 선택 | SVG 노드 11,806개인 가상 400핀 IC. 같은 브라우저 세션에서 클릭 16회, 개발 모드 React Profiler 중앙값 | 856.6→9.1ms. 클릭 시 React 렌더 구간 |
| 검증 진행 상황 대기 | 6초 폴링 측정 3회 중앙값 | 회로도 렌더 합계 789→0ms. 진행 상태 화면은 계속 갱신됨 |
| 대형 보드에서 핀 선택 | 가상 보드 210블록·검증 결과 1,560건. 목록 영역 별도 측정 | 부품 목록 184→32ms |
| 이력 10건 다시 열기 | 워밍업 후 Node 반복 계산 중앙값 / 브라우저 첫 로딩 최대 렌더 | 반복 계산 210.9→1.6ms / 첫 로딩 3,654→849ms |

## 포트폴리오에 쓸 문장

> 회로도의 핀을 선택할 때 무엇이 다시 그려지는지 React Profiler로 나눠 측정했습니다. 400핀 가상 IC에서 핀 행 단위로 갱신 범위를 줄여 클릭 렌더 중앙값을 856.6ms에서 9.1ms로 낮췄고, 화면과 내보내기가 공유하는 SVG 252종의 출력이 그대로인지 확인했습니다.

기존 소개에 대표 수치가 이미 있으므로 상세 화면에서는 ‘요소별 메모이제이션 뒤에도 남은 부모 순회 비용’과 ‘출력 동일성을 어떻게 확인했는가’를 이어 설명한다. 공개 화면에 넣는 예시도 기존 익명 샘플 보드 범위에서 선택한다.
