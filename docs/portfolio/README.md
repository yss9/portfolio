## 페이지에 반영하는 순서

1. 작업할 프로젝트의 문서에서 본인 역할과 시점을 확인한다. 상단에는 본인이 해결한 문제와 결과를 한 문장으로 쓰고, 상세 영역에서 사용자가 겪은 현상 → 구현 결정 → 검증한 결과를 연결한다.
2. 현재 노출 내용은 [프로젝트 등록 목록](../../src/content/projects/index.ts)과 해당 프로젝트 파일에서 확인한다. [프로젝트 이야기](../../src/content/project-stories.ts)도 함께 대조한다. 근거 코드·테스트를 표시하는 버전에서는 [근거 데이터](https://github.com/yss9/portfolio/blob/main/src/content/evidence.ts)를 확인한다.
3. 수치를 옮길 때는 측정 대상·환경·표본·단위를 같이 옮긴다. 개발 모드 렌더 시간, 로컬 JMeter 응답 시간, 합성 질의 품질, 코드상 DB 호출 수는 서로 다른 근거다. ‘테스트가 해당 동작을 검사한다’와 ‘이번 작업에서 테스트를 재실행했다’도 구분한다.
4. 원본이 바뀌면 해당 문서의 근거 링크에서 실제 버전과 결과를 확인해 문서와 공개 소개를 함께 갱신한다. 원본 소스가 비공개인 CIRGENT는 공개용 예시와 기존 측정 기록 범위에서 작성한다. 개인 계정 정보·실제 고객 보드·사내 경로는 공개 예시에서 제외한다.

## 비교 기준

기존 소개는 원격 포트폴리오 [기준 커밋](https://github.com/yss9/portfolio/tree/56a001c37df6b986136acefb25190debcf83a381)의 프로젝트별 데이터 및 로컬 상세 기록을 함께 참고했다. Glople은 [개편 병합 커밋](https://github.com/yss9/Glople/commit/bfcc41ef406635167d0b7f7d460473b7d0571b4f)을 포함한다. 문서의 측정값은 각 프로젝트의 기존 평가·벤치마크 기록에서 가져왔다.
